> 目标：让网站真正实现"一句话 / 完全随机 → 30-60 集完整短剧"的一键生成，面向完全不懂技术的新手小白。

## 一、同类项目调研结论

以下是公开仓库中与本项目目标最接近的 5 类项目，重点抓取了它们的架构与实现细节。

| 项目 | 技术栈 | 流水线实现细节 | 前端形态 | 可借鉴点 |
| --- | --- | --- | --- | --- |
| **waoowaoo**（AI 短剧工作台） | Next.js 15 + MySQL/Prisma + Redis/BullMQ + MinIO | 多 Provider 网关（LLM/生图/生视频可换供应商）；BYOK（用户自带 Key）设置中心；任务队列 + 计费冻结 | 后台工作台（项目/素材/任务/账单） | BYOK 模式：用户自己填 Key，平台不垫付 API 成本；多 Provider 网关做容灾 |
| **LocalMiniDrama**（本地短剧工厂） | Vue3 + Element Plus + @vue-flow + Express + SQLite | 8 步全流程：大纲→角色→分集→分镜→生图→视频→配音→合成；每步失败自动重试 3 次；已完成步骤智能跳过（断点续跑）；`@图片N` 引用 + 尾帧衔接；工程整体 ZIP 导入导出 | 本地图形化流程面板（拖拽式流程视图） | 断点续跑 + 重试策略；工程 ZIP 打包/恢复；步骤间数据引用约定（`@角色名`、`@图片N`） |
| **Open-AI-Micro-Drama-Generator** | FastAPI + Next.js 14 | 多 Agent 分工：编剧→角色→分镜→生图→生视频→moviepy 合成；`job_id` 异步任务；SSE 实时推送 7 阶段进度，断线自动重连 | Web 页面：输入题材 → 看到 7 阶段时间线实时点亮 | SSE 进度推送（我们目前是轮询，可升级）；多 Agent 提示词拆分方式 |
| **MoneyPrinterTurbo**（自动口播视频） | FastAPI + React + FFmpeg | 文案→TTS→配乐→字幕→素材混剪，模板化 | 网页 + 后台任务 | 素材混剪的稳定工程化；一键成片的产品化思路 |
| **PlotCat / Huobao Drama / OpenMontage**（剧本分镜 / 短剧平台类） | 混合 | 剧本结构化（场/镜/对白/动作）、分镜表、批量生图 | 编剧工具 / 平台 | 剧本数据结构化标准；批量资产管理的 UI 范式 |

**共同规律（也是我们已验证/已具备的）**：

1. 全部采用"大纲 → 角色 → 分集 → 分镜 → 图片 → 视频 → 音频 → 合成"的分阶段流水线，与我们的 9 阶段架构一致。
2. 全部用异步任务 + 状态持久化，长任务必须能重启、能续跑、能看进度。
3. 生图/生视频都用"角色一致性锚点（参考图/种子/尾帧）"来维持跨集形象统一。
4. 都有重试与失败恢复：步骤级重试 3 次、已完成步骤跳过。
5. 商业产品都做 BYOK 或充值计费，因为 API 成本是主要成本项。

| 成本项 | 估算区间 | 说明 |
| --- | --- | --- |
| 文本（DeepSeek：系列/角色/60 集剧本/分镜/小说） | ¥10-50 | 长剧大头在 60 集剧本，按 token 计费，用低档模型足够 |

- 新用户赠送体验金（当前 `signup_bonus_cents=1000` 即 ¥10），够生成 1 集真实快档尝鲜。
- 充值档位建议：单集档 / 10 集档 / 整剧 60 集档，整剧档折扣 + 失败包赔（自动重试）。

## 五、实施顺序（后续阶段）

### 阶段 8：60 集长剧架构（核心改造）

1. **大纲先行**：LLM 先生成"60 集大纲表"（每集 1-2 行：钩子/冲突/反转/悬念/结尾钩子），落库后再逐集生成剧本，保证全局连贯。
2. **持久化任务表**：`Task` 表增加 `episode_no`、`step`、`attempts`、`status`、`payload/result` 引用；任务表与文件产物一一对应。
3. **断点续跑**：worker 重启/失败后从最后未完成步骤继续；已完成步骤（文件存在 + 状态成功）直接跳过。
4. **失败自动重试**：每步重试 3 次（指数退避）；同一集连续失败则标记该集失败并告警，不拖垮整剧。
5. **按集预算**：每集冻结预算，超支自动暂停并提示。
6. **全剧一致性台账（核心新增）**：
   - `characters.md` 升级为"角色形象注册表"：每个角色固定 脸型 / 发型 / 瞳色 / 服装组合 / 标志配饰 / 体态 / 语速音色，任何图片与视频提示词都从注册表取字段，禁止自由发挥。
   - 新增 `scenes.md`（场景注册表）：每个场景唯一编号 + 固定视觉描述（光线/色调/道具/机位习惯），跨集引用同一编号即保证环境一致。
   - 新增 `style.md`（全局风格锚点）：色调 LUT、镜头语言、字幕样式、封面版式。
   - 生图固定 `seed`（基于角色/场景编号派生），生视频强制尾帧衔接 + 首帧引用上一集尾帧，跨集过渡片段单独处理。
   - 一致性校验：真实档开启后对角色图做相似度抽检（如 Seedream 参考图 + 简单人脸一致性打分），不合格自动重生成。
7. **分集交付规格**：每集独立 `final.mp4`（90-180 秒）＋ 单集 SRT 字幕；交付页展示"每集时长 + 全剧总时长"，可选生成全剧合集或每 10 集分卷。

### 阶段 9：SSE 实时进度 + 小白前端

1. 后端新增 `/api/projects/{id}/events` SSE 流（任务级进度事件：`episode` / `step` / `percent` / `message`），前端 `EventSource` 监听 + 断线自动重连（复用调研中的做法）。
2. 前端：题材模板库（10 个热门模板一键填充）、新手三步引导（输入/点生成/等交付）、任务中心列表（进度条 + 可继续）、成本与时长预警弹窗。

### 阶段 10：成本控制与收款

1. 火山资源包预检：生成前查询余额/套餐余量，不足则阻止并提示。
2. 计费细化：按实际 token/时长记账（当前是粗略占位公式，见 `backend/app/routers/projects.py` 的 `estimate_cost`）。
3. 支付：先做 BYOK（用户填自己的 Key，平台 0 垫资）；有商户号后接微信/支付宝充值。

### 阶段 11：上线与运营

1. 域名 + HTTPS（备案/反代配置）。
2. AI 内容标识 + 敏感词过滤 + 投稿规格适配（各平台封面/时长/字幕规范）。
3. 运营文档：定价页、使用教程、故障排查（"为什么视频卡住"）。
